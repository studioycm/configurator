## 1. Model/document and six initial definitions

Add only nullable JSON `groups.catalog_attributes`, no default/backfill or index. Migration `2026_10_31_000001_add_catalog_attributes_to_groups_table.php` is currently absent; recheck filename/order at release. NULL and `{}` both mean no assigned attributes. Do not initialize existing Groups through Save or create engineering facts. Add the Group array cast only; no broad mass-assignment expansion, relation or Configurator Attribute reuse.

`config/group_attributes.php` holds ordered supported keys, translation label keys and limits: `operating_pressure` → Operating Pressure; `application` → Application; `system_water_flow_rate` → System Water Flow Rate; `required_function` → Required Function; `fluid_type` → Fluid Type; `installation_type` → Installation Type. Six is the initial registry; a later definition/config entry requires no extra database column. Dynamic definition-manager UI is not part of GA1. Future well-formed stored keys survive older-form saves even when not displayed.

Document shape is an object mapping attribute keys to ordered lists of strings. Technical bounds:32KiB standard JSON-encoded whole document and raw submitted changes;25 values/key;200 Unicode characters/value; valid UTF-8 and no NUL; nonblank values. No numeric ranges/units/calculations. Reject typed numbers/booleans/null/objects as cells, nested lists, list-shaped document roots and duplicate exact values after new-entry normalization. `"0"`, `"001"`, case, Unicode and internal spaces remain literal strings, never option IDs/numbers.

**New authoring versus retained data:** TagsInput's createTag() trims only its newly entered buffer, uses exact state.includes and does not rewrite hydrated array values. Use this ordinary surrounding-whitespace trim for **new Group labels**; it is not the exact identifier rule from Product/configuration codes. The writer mirrors **ECMAScript String.trim() exactly**, preserving case/Unicode/internal/multiword text. Do not use Laravel Str::trim, PHP trim, \s or a broader invisible-character category: they do not define the same set. An exact value already present in that same Group/key's fresh stored list bypasses new-entry trim and stays byte-for-byte, including surrounding whitespace. Reject blank/duplicate results rather than infer data. Native form validation/retention uses the same fresh-document context. No blanket trim of stored JSON or loaded form arrays. For example, an unchanged stored `" 0 "` stays `" 0 "`; adding a new padded `" 001 "` authors `"001"`. Existing and new exact-distinct strings are not merged by numeric/case normalization. Initial new facts can be manually entered later or supplied by a separately approved Group-ID/key/value mapping; no import in GA1.

**GA1-TRIM-PARITY-001 correction:** implement one small private service `trimNewEntry(string $value): string` with an explicit Unicode-safe, start/end-only character class: U+0009–U+000D, U+0020, U+00A0, U+1680, U+2000–U+200A, U+2028–U+2029, U+202F, U+205F, U+3000, U+FEFF. These are ECMAScript WhiteSpace/LineTerminator characters. Use `\A`/`\z` anchors and `/u`; validate UTF-8 first, with no fallback to a different trim rule. Nonblank for new entries means this exact trim result is nonempty. U+200B (zero-width space), U+200C (ZWNJ), U+200D (ZWJ) and U+00AD (soft hyphen) are **not** trimmed and remain exact; do not add an unstated rejection. The existing NUL/type/size rules still apply. Existing-value bypass and faithful stored/filter transport are unchanged; no general Unicode framework or new file.

Use the same small literal vector list in the already-planned PHP operation/native tests and actual-TagsInput Node contract (duplicate these few data literals, not the algorithm or a new fixture file): space-wrapped `0` → `0`; NBSP-wrapped `001` → `001`; BOM-wrapped `é Multi Word` → `é Multi Word`; and each of U+200B/U+200C/U+200D/U+00AD wrapped around `0` → **unchanged exact string**. Assert the non-ECMAScript variants do not silently collide with existing `0`, and unchanged retained lists survive native Save byte-for-byte. Client uses the actual installed factory; PHP uses the actual writer/readback with independently specified expected outputs. This pins client/server persistence parity, not vendor implementation text.

Omitted document/key means preserve its **fresh stored** value; explicit per-key `[]` clears that key, not the whole document. Empty changes map is a no-op. Unknown submitted keys reject; unsubmitted well-formed future keys persist. Persist changed maps as JSON **objects at the top level** (e.g. `(object)$map` through the current cast), retaining value arrays; never globally JSON_FORCE_OBJECT. No-op saves preserve NULL versus{} representation, raw valid data, timestamp and revision. A malformed stored document is not repaired/emptied on read: show authoring unavailable, disable/dehydrate no attribute inputs, preserve it on ordinary saves; forged nonempty attribute changes reject. No repair operation is introduced.
