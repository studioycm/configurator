## Current source and responsibility boundaries

- `CatalogCards` already chooses configured `card_properties` (snapshot construction falls back to actual Group filters), uses `CatalogCardDisplay` for card-only differences over the entire matching set and emits 24-card HTML chunks. Comparison must not reuse those already-suppressed card rows: it reads the full configured key list and partitions two current saved values itself.
- `CatalogPolicy::resultSettings` owns configured key normalization; `ProductEditorData::groupFields` supplies actual Group-filter labels/order, distinct from editor_properties. Preserve those meanings. Existing card-cell semantics are nonempty string or missing, with no trimming, numeric conversion or case folding.
- `CatalogAvailability` owns visible ancestry and disabled-Configurator policy but `productIsVisible` alone does not enforce physical leaf. Reuse its Group read once, explicitly reject physical branches, then require both active Products directly owned by that Group.
- GroupShow has locked Group identity and JSON card commands. Its filter root is `wire:ignore`; injected chunks remain Alpine-owned. The comparison command must return JSON without rerendering or replacing that root.
- A Product card has exactly one full-content Product link with existing href/return/focus bindings. Add its Compare button **outside** that anchor. `card-chunk` is produced only by CatalogCards; use it to opt into Compare controls. Default direct Product-card rendering remains unchanged.
- `catalogFilters.publish` already computes full matching IDs locally. Use that existing result only to update two selection-membership flags, without storing another result-ID collection, issuing filter-state requests or changing the filter engine.
- Keep K4 presentation/facts/Parts/journey and K5 exact-code/Preview/failure/URL ownership. Comparison adds no URL parameter or history writer, storage, configuration action, schema, image adapter or real image. Use the existing truthful image-placeholder component in the comparison header.

Row: `{key:string,label:string,values:[?string,?string]}`. No complete profile maps, Parts, runtime, client criteria or image metadata enter the payload.

- [ ] Write failing feature cases for exactly two distinct canonical positive IDs in caller order; malformed/list/map/extra/missing/duplicate/foreign IDs; missing actor, hidden ancestry, physical branch, inactive/deleted/reassigned Product. - [ ] Validate at command and service boundary before querying: list of exactly two IDs, each positive integer or canonical decimal string fitting the platform integer range; reject booleans/floats/exponents/leading-zero identities and duplicates after canonical validation. - [ ] Perform one bounded read transaction: current visibility graph once, actual leaf Group with filters, two active directly owned Product rows and current result_settings.
