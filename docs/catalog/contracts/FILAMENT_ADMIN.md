# Implementation contract: Filament administration

Updated 2026-09-23. **Detailed execution contract, not an implemented interface or a complete UX audit.** The [decisions](../DECISIONS.md) control user behavior; [data/engine](ENGINE_AND_DATA.md) controls model/ID/operator contracts; [public](PUBLIC_CATALOG.md) controls discovery routes and Group settings. The final [plan](../IMPLEMENTATION_PLAN.md) and [guidelines](../IMPLEMENTATION_GUIDELINES.md) select the technical defaults below. Earlier “proposed” wording distinguishes provenance from explicit user decisions, not a second review gate. The UX/Filament/Livewire/testing evaluation informed this contract; imported Laravel Simplifier remains opt-in.

Reviewed stack: PHP 8.4, Laravel 13.33.0, Filament 5.8.4, Livewire 4.4.6, Pest 5.2.1; `.ai/rules` was absent. Refresh environment facts in T01. This preparation changed documentation only; the new session's instruction establishes implementation scope, with database/release boundaries in the plan.

## 3. Configurator page and action boundaries

Proposed target `app/Filament/Resources/Configurators/Pages/EditConfigurator.php` owns a full-width schema with exactly these four tabs. It can retain an EditRecord route while replacing the default broad form Save with explicit header/modal actions and owner-scoped components.

```text
Configurator: [name]                 [Settings] [Assign groups] [Duplicate]
Applies to N leaf Groups · shared edits affect these assignments [View groups]

Attributes | Rules | Preview & Test | Custom

Attributes: [Include attribute] [Code order]        display-order drag table
  Attribute | Input | Included options | Default | Code position | Edit | Remove

Rules:      [Add mapping] [Add advanced rule]       highest-priority-first table
  Rule | Type | Driver → Target / effect summary | Enabled | Edit | Remove

Preview & Test: Saved definition · Product [product_code] · Territory · Application
  Same runtime controls/result as public configurator + rule diagnostics

Custom:     Reserved for later custom behavior.
```

Layout: `Filament\Schemas\Schema` uses `$schema->columns(1)`; `Filament\Schemas\Components\Tabs::make('Configurator')->key('configurator-editor')->persistTabInQueryString('tab')->columnSpanFull()`, four `Filament\Schemas\Components\Tabs\Tab::make(...)` children. [Tabs docs](https://filamentphp.com/docs/5.x/schemas/tabs). Use `Filament\Schemas\Components\Section::make(...)->columns(2)->columnSpanFull()` for two-field groups and one-column/full-width repeaters or matrix content; [layouts](https://filamentphp.com/docs/5.x/schemas/layouts). No nested accidental quarter-width fields.

Owner-scoped relation managers can be inserted with `Filament\Schemas\Components\Livewire::make(AttributesRelationManager::class, ['ownerRecord' => $record, 'pageClass' => static::class])->key('attributes-'.$record->getKey())` and an equivalent separately keyed Rules manager. The installed schema component accepts serializable component data; these are independently saving components, not a channel for the parent's unsaved state. [Livewire schema components](https://filamentphp.com/docs/5.x/schemas/custom-components#inserting-a-livewire-component-into-a-schema). Their public methods reauthorize and re-resolve the trusted owner.

Keep ordinary rendering initially. The inspected Filament 5.8 deferred-tab project proves `Filament\Schemas\Schema::deferLoading()` after a stable key and validation-triggered loading, not atomic preservation of arbitrary unseen associations. Add deferral only after measuring an actual expensive section; read-only Preview is a safer first candidate. Unvisited-tab save coverage is a prerequisite if editing schemas later use it. Deferral is a performance choice, never the domain hidden/inapplicable state.

All actions below are `Filament\Actions\Action` using [action schemas](https://filamentphp.com/docs/5.x/actions/modals) and [actions overview](https://filamentphp.com/docs/5.x/actions/overview). Use `->schema(...)`, `->fillForm(...)`, `->action(...)`; keep the inherited 7xl width. Mutations use `->authorize('manage-catalog')` and explicit `Gate::authorize('manage-catalog')` in the invoked action/service boundary. Hidden/disabled controls are only presentation.

| Action / location | Visibility and commit contract |
| --- | --- |
| Create Configurator / list header | Admitted administrator; `name` and description only, optional agreed context vocabulary settings. Creates an unassigned definition; no guessed Attribute/code/rule seed. Opens the edit page. |
| Settings / page header | `name`, description and fixed Territory/Application choice metadata. Save only these settings after validating allowed keys, value identity/uniqueness and existing rule references. No raw `policy_overrides`, JSON-rule textarea, stage controls or arbitrary runtime-context schema editor. |
| Assign groups / page header | Searchable multiple leaf-Group select; choices are unassigned Groups plus this Configurator's current assignments. Save the explicit desired set atomically; no silent reassignment from another Configurator. A Group's own assignment field can explicitly change its single assignment. No ancestor inheritance. |
| Duplicate / page header | Name required. Domain clone allocates fresh ConfiguratorAttribute/ConfiguratorOption/rule IDs, remaps local defaults/conditions/effects/mappings, and shares canonical Attribute/Value/Option records. The technical proposal is to copy no Group assignments; assignment is explicit afterward. Generic `ReplicateAction` without this remap is insufficient. |
| Include/Edit Attribute / Attributes table | Whole local inclusion is staged; one Save validates membership/default/references and persists all its local option changes. Edit must resolve inclusion under the page Configurator, not by an unscoped submitted ID. |
| Code order / Attributes toolbar | Ordered complete list of this Configurator's included Attributes; save only `code_order`, never display order/default. Repeater has reorder buttons as well as drag. |
| Add/Edit mapping or advanced rule / Rules table | One staged whole-rule Save for conditions, effects and all mapping sets. Kind is fixed when editing; converting kind is not an implicit data-destroying select change. |
| Remove inclusion/rule or delete shared definition | `->requiresConfirmation()` and human-readable impact/references. Domain validation under locks remains authoritative. Do not use blind cascade/delete bulk actions. Removing a referenced/default option fails until an explicit repair is made. A rule removal is an explicit removal of its owned conditions/effects/sets in the same transaction. |

## 4. Shared fields, columns and local editing

All text is escaped by default. Select labels include code/Attribute context where labels could repeat; IDs, not labels, carry identity. Every selected existing ID is re-resolved server-side. A searchable select's options query is not sufficient authorization.

Set the initial default candidate once, when the first option is included in a new inclusion. Preserve it through later reorder and editing. Removing the chosen candidate requires an explicit replacement; neither `fixIndistinctState()` nor `afterStateUpdated()` may silently choose a new default. If a stored default is temporarily hidden/disabled at runtime, engine fallback handles that without overwriting the stored default. Removing a row used by a rule similarly shows the referencing rule(s) and blocks Save until explicit repair.

Reactive UI uses `Filament\Schemas\Components\Utilities\Get` / `Set` and `->live()` only where another field needs updated choices. [Field reactivity](https://filamentphp.com/docs/5.x/forms/overview#reactivity). Changing an upstream field must not silently null persisted default/mapping targets. Preserve invalidated draft state with a clear error or require explicit removal/replacement. `$set()` does not invoke another field's update hook by default; domain correctness must not depend on a chain of hooks.

Initial `defaultSort('product_code')`, stable ID secondary order. |

`Filament\Tables\Table` [table docs](https://filamentphp.com/docs/5.x/tables/overview) owns pagination and record actions. Keep mutation out of `ToggleColumn`/inline cell callbacks where that bypasses whole-definition validation; Enabled is changed in the whole rule dialog. A usage action shows affected Configurator/Attribute/rule/Group names with internal edit links and counts, not raw exception details.

Display-order and rule-priority dragging use table `->reorderable('display_order')` and `->reorderable('priority', direction: 'desc')`; [reordering](https://filamentphp.com/docs/5.x/tables/overview#reordering-records). Override the owning component's `reorderTable(array $order, int|string|null $draggedRecordKey = null): void` to call an authorized, owner-locked domain action. Require an exact unique permutation of the relevant owner's complete record set, clear/filter-disable the reorder view, and write dense ranks atomically. Priority top becomes highest; no manual integers. A move-up/down action can call the same reorder service for keyboard access. Native `beforeReordering()` runs before its internal transaction and is insufficient to hold a definition lock across the write. Never allow partial filtered rows to overwrite other owners' order.

## 5. Rule conditions and allowed-option matrix

Follow exactly the engine annex's `ConfiguratorRule`, root All, one-level `RuleConditionGroup` All/Any, typed condition/operator registry, `RuleEffect` and mapping-set shapes. The UI cannot widen them. Existing codes shown in condition choices are resolved from included local options; no whole assembled-code source, SQL expression, arbitrary JSON path or recursive group builder.

| Field | Component and docs | Validation / configuration |
| --- | --- | --- |
| rule `label`, `is_active` | `Filament\Forms\Components\TextInput`, `Filament\Forms\Components\Toggle`; [text](https://filamentphp.com/docs/5.x/forms/text-input), [toggle](https://filamentphp.com/docs/5.x/forms/toggle) | `label->required()->maxLength(255)`; enabled boolean, initial true. Priority is managed by drag, not entered here. |

| predicate source and operand | `Filament\Forms\Components\Select`, conditional `Filament\Forms\Components\TextInput`; [select](https://filamentphp.com/docs/5.x/forms/select), [text](https://filamentphp.com/docs/5.x/forms/text-input) | Source is SelectionOption/SelectionCode, registered ProductProperty, Territory or Application. | Mapping driver/target | `Filament\Forms\Components\Select`; [select](https://filamentphp.com/docs/5.x/forms/select) | `->required()->searchable()->live()->options(...)`; IDs are this Configurator's **ConfiguratorAttribute IDs**. A Mapping has exactly one pair. Cross-owner and cyclic selections fail whole-definition validation. |
| Mapping sets | `App\Filament\Forms\Components\MappingSetsField` extending `Filament\Forms\Components\Field`; [custom fields](https://filamentphp.com/docs/5.x/forms/custom-fields) | `->required()->columnSpanFull()` with server validator for complete typed set state; custom Blade uses standard form field wrapper and state-binding modifiers. No automatic relationship saver. |
| Advanced effects | `Filament\Forms\Components\Repeater`, `Filament\Forms\Components\Select`, `Filament\Forms\Components\TextInput`; [repeater](https://filamentphp.com/docs/5.x/forms/repeater), [select](https://filamentphp.com/docs/5.x/forms/select), [text](https://filamentphp.com/docs/5.x/forms/text-input) | At least one effect; kind allowlist from engine; target local Attribute required; local option IDs required and nonempty for option-scope effects; text required for scalar effects; reject irrelevant unknown payload fields. `ExcludeOptions` is a secondary advanced effect, not the default matrix editing mode. |

Generate the custom field only during implementation with `php artisan make:filament-form-field MappingSetsField --no-interaction`. Target class `app/Filament/Forms/Components/MappingSetsField.php`; view `resources/views/filament/forms/components/mapping-sets-field.blade.php`. A Field is not its own Livewire component. Bind to the owning form state using `$getStatePath()` and `$applyStateBindingModifiers(...)`; Alpine may manage immediate checkbox interaction, but the server rebuilds trusted state and performs the sole persistence operation. No extra JavaScript dependency is justified.

The matrix's logical rows are mapping sets: a short optional label, one or more driver options, and checkboxes for allowed target options. Show a compact driver-membership panel next to the target grid; include code + local label, set/source counts, target counts and an Add set / Remove set control. `Filament\Forms\Components\CheckboxList::make(...)->options(...)->searchable()->bulkToggleable()` is a valid fallback inside a set editor ([checkbox lists](https://filamentphp.com/docs/5.x/forms/checkbox-list)); the custom Field coordinates all sets and duplicate-source feedback.

Required invariant feedback:

- A saved set has at least one source and target. Each source appears in at most one set of this Mapping. Target overlap between sets is valid. Not every included driver option must be covered; explicitly say “Unmapped driver options add no restriction.”
- Add/remove/check actions change only draft state. Save validates all sets, conditions, local memberships, cycles and references, then persists the complete rule in one transaction. No per-cell `sync()`, live model mutation or delete-all/recreate-all callback.
- Changing driver/target with populated sets preserves draft selections and reports incompatibility until explicit repair. It cannot silently discard sets or map similarly labelled foreign options.
- Keep persisted set/condition/effect IDs stable where records survive. New staging keys never authorize an existing record. Stale/missing source or target options remain visibly identified as repair errors, rather than disappearing from the posted state.
- Grid headers identify target codes; each checkbox has a full accessible source/set/target label. Keyboard and focus order must match logical rows, scrolling must retain labels, and narrow screens may use the same set editor without a dense grid. UI tests must verify this; the research did not perform an assistive-technology audit.

This is a bounded custom-field feasibility conclusion. The inspected many-to-many checkbox matrix supplies layout/fill ideas, while its per-record relationship sync is incompatible with this save contract. The quote picker supplies searchable selection composition, while its delete/recreate persistence and private Livewire hook are not transferred. The QueryBuilder example's maximum nesting controls do not replace a rejecting server parser for this rule language.

## 7. Authorization, validation, failure and preview lifecycle

Define one application gate, proposed name `manage-catalog`, whose authenticated `App\Models\User` decision calls the same `canAccessPanel(Filament::getPanel('admin'))` admission predicate. The known panel ID is trusted server configuration, not a client parameter. Do not copy the actual allowed addresses into documentation or duplicate the allowlist in policies. No new roles, permission tables or authorization dependency.

Add resource policies/authorization methods where needed for framework record actions, each delegating to that gate. Custom page actions, relation-manager methods, reorder, canonical updates, aggregate saves, Group assignments and import adapters explicitly invoke the same gate at execution. Read-only Preview still requires admitted-panel access, and re-resolves Product scope. [Filament security](https://filamentphp.com/docs/5.x/advanced/security), [authorization](https://filamentphp.com/docs/5.x/resources/overview#authorization), [Laravel gates](https://github.com/laravel/docs/blob/13.x/authorization.md#gates). `canAccessPanel()` protects panel admission; it is not itself an automatically called policy for every custom mutation.

The mandatory mutation sequence is:

1. Reauthorize, resolve the owner from trusted route/component identity, reject unknown payload keys, parse typed state and canonical/local ID kinds.
2. Begin the domain transaction and acquire the engine annex's deterministic owner/affected-definition locks. Re-read current references and related records. Validate the **complete proposed aggregate**, including preserved records, removed references, default membership, code uniqueness, scope and cycle rules, before any relationship writes.
3. Apply only the validated diff, preserving surviving local/rule/set IDs. Resolve new staging keys, assign default IDs, and write calculated ranks within that transaction. Database FK/unique constraints remain the final concurrent guard. Commit once.
4. On success close only that action modal, refresh affected owner tables/counts, and show a brief success notification. On failure roll back, retain submitted form state and focus/identify field or set errors. A malformed or stale record never becomes a best-effort partial save.

Installed `Filament\Resources\Pages\EditRecord::save()` calls `getState()` before `mutateFormDataBeforeSave()`, and `getState()` may invoke relationship savers. Consequently these staged actions use plain state fields and explicit domain persistence, not `->relationship()` repeaters relying on a late mutation hook to prevent writes. The PHP validation/action boundary is authoritative even if the form has not visited a tab.

Use `Illuminate\Validation\ValidationException` with correct nested paths for actionable input errors. A bounded form-level explanation can use `Filament\Schemas\Components\Callout::make(...)->danger()->description(...)->visible(...)` ([callouts](https://filamentphp.com/docs/5.x/schemas/callouts)). Catch unexpected failures after rollback, log private technical details, and show a safe retry/reference message; no SQL, stack trace or raw exception text. `Filament\Actions\Action::halt()` defaults to rollback **false** in installed 5.8.4. If a Filament-managed transaction must be aborted, use `halt(true)`; halting UI flow is not transaction safety. Prefer a single domain transaction rather than ambiguous nested framework/action transactions.

Preview reads the saved current definition only and visibly says so. Pick an actual Product from this Configurator's assigned leaf Groups with a searchable `Filament\Forms\Components\Select` labelled by `product_code`, then the agreed single-select Territory/Application context choices (All initially). Feed trusted Product facts and local option IDs to the same compiler/evaluator as public runtime. Existing enum input types map to `Filament\Forms\Components\ToggleButtons` ([toggle buttons](https://filamentphp.com/docs/5.x/forms/toggle-buttons)) or `Filament\Forms\Components\Select` ([select](https://filamentphp.com/docs/5.x/forms/select)), single selection, with engine-supplied legal/hidden/disabled states. Invalid forged selections are rejected by the server regardless of disabled HTML. Render resulting code/completeness and diagnostics from that single settled result; no second implementation of rule logic in the form.

No Save, database-backed visitor configuration, Product mutation or rule mutation occurs during Preview. Product absent/unassigned gives an honest empty state. Refresh/re-evaluate is a read action, and current settings/rules are reloaded on subsequent actions. Unsaved-modal preview is a separate future choice requiring an explicitly labelled in-memory definition path; do not accidentally preview half of a pending form with half of persisted relationships.
