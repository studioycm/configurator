## 2. Models, roles and eligible sets

`Group.parent_id` is actual hierarchy. A Product belongs directly to one Group through `products.group_id`. `GroupFilter` defines a dynamic Product field and display vocabulary/order; `SubGroup` is an atomic Product filter **preset**, not a child Group. Group has optional Configurator assignment; Product facts are `profile_fields`, Parts are separate `parts`. Group has no modelCode or role/type; the initial inspection lacked managed images, while the current minimum CODE+TEST package now supplies Asset+nullable main_image_id. Main rollout remains unrun (§26). Parent/leaf role is derived from actual hierarchy and existing supported operations, not name/legacy code or a filtered child count.

Source proof: `CatalogIntegrity::assertLeaf`, `validateGroup`, Configurator assignment and Group filter/settings writes enforce leaf ownership; `ImportCatalogProducts` refuses proposed parent paths carrying Products/Configurator and cycles; `BuildCatalogSnapshot`/`CatalogSnapshots::revision` reject physical branches. These support the initial end/model predicate. FKs alone do not enforce leaf role, and `CatalogAvailability::productIsVisible` alone does not reject a legacy branch-owned Product. No live data inventory was run; an actual contradictory record is not established.

Define E = Groups admitted by `CatalogAvailability` (active Group, active/visible ancestry and Configurator hide policy), with **no physical children** and EXISTS at least one directly owned active Product admitted by the current Product visibility policy. This is not childless alone. Empty/inactive-only leaves have no card; hidden physical children do not turn parents into leaves; disabled-but-visible or unassigned Configurator does not suppress otherwise eligible Products. No requirement that the Configurator can generate a code before a model appears. Orphan/cyclic/unavailable paths remain excluded by availability.

At root, B=E. On an organizing branch, B is E under that actual branch; selecting a model can set B to that model. R is B after first-page search and tag choices. Cards and total use R. Tree disclosure/loaded sibling slice never changes E/B. Parent names select branch context, plus expands only; a model card opens its Group Products route. Tree model selection narrows to its card; the card is the explicit Products entry. No navigation through parent cards.

Tag options derive from tags assigned directly to B, before current optional tags; no automatic ancestor-tag inheritance. Values within category OR, categories AND. Matching counts, if enabled, mean number of model Groups in B carrying that value; label that basis, not projected Products/option compatibility. Branch badges count eligible models in that branch. Optional card Product count is separately labeled active direct Products, never confused with model count. Unavailable choices on a new branch follow shared keep-still-available/clear behavior and explain removals; zero-result compatible Group tag combinations are not auto-cleared. Back/Forward restores recorded state without applying a new-entry reset again.

Before runtime activation on actual data, an approved nonmutating inventory must identify mixed parent+Products/Configurator, empty/inactive-only leaves, hidden ancestry and orphan/cycle anomalies. If found, report safe IDs/counts and contract conflict; do not migrate/reclassify/widen access automatically. Such evidence may block affected records/package, not every independent feature. This audit makes no assertion about the retained preview DB contents.
